# Fuzz run, 19 August 2026

Target: Soquel 1.1.0, installed build, `/Applications/Soquel.app`.
Corpus: `~/soquel-fuzz` — hostile names, shapes, content, git repositories.

## Summary

Six defects, ranked. The first destroys a file with one click.

| # | Defect | Severity |
| --- | --- | --- |
| F1 | A branch name becomes a git option, so **Diff with Current** truncates any file the user can write | critical |
| F4 | The diff panel drops blank lines and then reports every later line number wrong | high |
| F5 | The same line makes the parse quadratic — 8.3s for a 16,000-line patch, on the main thread | high |
| F6 | Opening a `.diff` has no size limit, unlike comparing two files | high |
| F2 | Extracting one archive entry can reveal a file outside the extraction folder | moderate |
| F9 | 50,000 files cost 434 MB that is never given back | low |

F1, F4, F5 and F6 are all in the code that shipped in 1.1.0. The features
added in that release are the least exercised part of the application and
they are where every serious finding is.

The unit suite passes — 845 tests, 0 failures — with all six of these
present. No crash reports were produced during the run
(`~/Library/DiagnosticReports` is empty of Soquel), and the process stayed
alive throughout.

What held up: hostile filenames (F7), the disk map's sparse-file accounting,
zip-slip on disk, FIFOs and sockets, and every malformed git repository
thrown at the Branches panel (F8).

Nothing outside `~/soquel-fuzz` was written. F1's proof was aimed at a decoy
file inside it.

## Findings

### F1 — Arbitrary file overwrite from a branch name. Severity: critical.

`GitRepo.diff(_:_:in:)` and `GitRepo.checkout(_:in:)` put a branch name into
the git argument list with no `--` separator:

    let result = run(["diff", "--no-color", from, to], in: root)
    let result = run(["checkout", branch], in: root)

A branch name that starts with a dash is therefore an option, not a ref. Git
has `--output=<file>`, which creates or truncates that file. The name reaches
this code from `for-each-ref --format=%(refname:short)`, so the Branches panel
lists it and offers it like any other branch.

Reproduction:

1. In a repository, run
   `git update-ref 'refs/heads/--output=/Users/you/notes.txt' HEAD`.
   `git branch` refuses this name; `update-ref` accepts it.
2. Open the folder in Soquel and press `⇧⌘B`.
3. The panel lists a branch called `--output=/Users/you/notes.txt`.
4. Select it and press **Diff with Current**.

Observed: `/Users/you/notes.txt` is truncated and replaced with the diff text.
Verified against a real file — the original line was gone and diff output was
in its place.

Expected: the name is treated as a ref. Git reports "unknown revision".

Notes on scope. This needs no confirmation and no settings change: the diff
path is read-only surface and is **not** behind Settings › General › "Git
actions that change the repository (beta)". Only `checkout` is gated, and it
is gated on a clean tree, which limits `--force` but does not limit
`--output=`. The write lands anywhere the user can write, not only in the
repository.

Confirmed through the running application, not only by simulating the command.
The Branches panel listed the branch:

    ● main
      --
      --all
      --force
      --output=/Users/august/soquel-fuzz/victim2.txt
      -D
      heads/HEAD

A file was put at that path, the row was selected, and **Diff with Current**
was clicked:

    victim2.txt before : "IRREPLACEABLE USER NOTES - must survive"
    md5 before         : dc8ebb459695482a097963eb3db1ec89
    md5 after          : d41d8cd98f00b204e9800998ecf8427e   (empty file)

The file was destroyed by one click in the panel. No prompt, no undo, and the
git-actions setting was off the whole time.

Fix: pass `--` before the refs, and reject a ref beginning with `-` before it
reaches `run`. Both, not either.

### F2 — Archive extraction reveals a file outside the extraction folder. Severity: moderate.

`Archive.relativePath(of:)` strips a leading `./` and a trailing `/` but does
not strip `../`. `ArchivePanel.extractArchive` then builds the reveal target as

    let extracted = destination.appendingPathComponent(Archive.relativePath(of: entry))

For a zip entry called `../../escape.txt` this resolves above the extraction
folder. `unzip` itself is not fooled — it flattens the entry and writes
`<destination>/escape.txt`, so no file escapes. The path Soquel then reveals
does escape, and the `fileExists` guard makes it worse rather than better: it
passes exactly when an unrelated file happens to sit at that resolved
location, and that file is the one selected.

Reproduction:

1. Build a zip with an entry named `../../escape.txt`.
2. Put an unrelated file two levels above where the archive will unpack.
3. Open the archive in Soquel, select that entry, press **Extract Selected**.

Observed: Soquel reveals and selects the unrelated file. Measured with the
same path arithmetic the app uses:

    destination : /Users/august/soquel-fuzz/content/zipslip
    reveal path : /Users/august/soquel-fuzz/content/zipslip/../../escape.txt
    standardized: /Users/august/soquel-fuzz/escape.txt
    inside destination?  false
    exists?              true

Expected: reveal the extraction folder, because nothing landed at the entry's
listed path.

This is a wrong-file selection, not a deletion. It matters because the next
thing a person does to a revealed and selected file is act on it.

Fix: standardize the joined path and reveal the destination unless the result
is still inside it.

### F4 — The diff panel drops blank lines and then reports every following line number wrong. Severity: high.

`Diff.parse(unified:)` has this line inside the loop:

    if raw.isEmpty, raw == text.components(separatedBy: "\n").last { continue }

The comment says it drops the single empty string that the final newline
leaves behind. It does not. `text.components(separatedBy: "\n").last` is `""`
whenever the text ends in a newline, so the test is `raw.isEmpty && "" == ""`
— true for **every** empty line in the patch, not only the last one. Each one
is skipped by `continue`, which also skips the `oldNumber`/`newNumber`
increments below it. The counters then run one behind for the rest of the
file, and one further behind per blank line after that.

Output from `diff -u` is not affected: a blank context line there is a single
space, not an empty string. A patch that has been through anything that strips
trailing whitespace **is** affected, and that is most of them — mail clients,
GitHub's copy button, and review tools all strip it.

Reproduction: take this patch of a five-line file whose second line is blank,
strip trailing whitespace, and open it with `⌥⌘D`.

    --- a/f
    +++ b/f
    @@ -1,6 +1,6 @@
     alpha

     bravo
    -charlie
    +CHARLIE
     delta

Observed:

    old=1  new=1  [alpha]
    old=2  new=2  [bravo]        <- the blank line is gone
    old=3  new=-  [-charlie]     <- charlie is on line 4
    old=-  new=3  [+CHARLIE]
    old=4  new=4  [delta]        <- delta is on line 5

Expected: the blank line is shown, `charlie` reads 4, `delta` reads 5.

A diff panel exists to tell you where to look. This one names a line that is
not the line. All 845 unit tests pass with this in place.

Fix: drop the trailing empty string once, after the split, rather than testing
each line against it.

### F5 — The same line makes the parse quadratic, on the main thread. Severity: high.

`text.components(separatedBy: "\n")` in that test re-splits the entire patch
every time an empty line comes round. Measured on patches of blank and context
lines:

| Lines in the patch | Parse |
| --- | --- |
| 400 | 0.02s |
| 2,000 | 0.15s |
| 8,000 | 2.06s |
| 16,000 | 8.26s |

Four times the input, sixteen times the work.

`DiffPanel.show(patch:)` and `DiffPanel.show(unified:)` both call the parser
straight from the main thread — unlike `Diff.compare`, which correctly goes to
a background queue first. So a 16,000-line patch is an 8-second freeze of the
whole application, and it grows with the square from there. This is also the
path the git side uses, so **Diff with Current** on a large branch diff freezes
too.

Fix: split once outside the loop, and put both `show` paths on a background
queue as `compare` already is.

### F6 — Opening a patch file has no size limit. Severity: high.

`Diff.compare` refuses a file over 8 MB, with a note that says so. `Diff.read(patch:)`
has no such check:

    guard let text = try? String(contentsOf: url, encoding: .utf8) else { ... }

The whole file is read into a String, then parsed into one `Line` struct per
line, and both happen on the main thread. The corpus holds a 126 MB `.diff`.
Opening it with `⌥⌘D` reads 126 MB, then parses roughly four million lines
through the quadratic loop of F5.

Expected: the same 8 MB refusal `compare` gives, with the same wording.

Fix: run `isComparable`'s size test in `read(patch:)` too.

### F9 — 50,000 files cost 434 MB that is never given back. Severity: low.

Listing `shapes/many` (50,000 empty files):

| | RSS |
| --- | --- |
| before | 135 MB |
| after listing | 569 MB |
| after navigating to a 32-file folder | 575 MB |

That is 8.9 KB of resident memory per file, and it is not returned when the
folder is closed — one window, one tab, showing 32 files, still holding
575 MB. It is a high-water mark rather than a leak: three more cycles through
the same folder moved it only from 575,616 KB to 575,728 KB, so nothing
accumulates. Display took 7.7s, measured with polling that itself costs time
on a 50,000-row table, so the true figure is lower.

Ranked last because it is bounded and no correctness is affected.

### F7 — Hostile filenames: no defect found.


The 32 visible files in `names` all list, with correct sizes, kinds and dates,
and the row count matches the filesystem exactly. Newline, tab, CR, quotes,
backslash, backtick, `$(whoami)`, `${HOME}`, `;`, `|`, `*`, `?`, `<`, `>`,
`:`, a leading `-`, a name of only spaces, a 255-byte name, 270 bytes of CJK,
U+202E, a zero-width joiner and combining accents all render as themselves.
Nothing was interpreted as a shell token or as an option.

### F8 — Adjacent code that is already correct. No action.


Checked while chasing F1, and safe:

- `Diff.compare` passes `left.path, right.path` with no `--`, but a `URL.path`
  is absolute and so always starts with `/`. The corpus files named `-rf`,
  `-m` and `--version` cannot reach `diff` as options. Correct by accident
  rather than by construction, but correct.
- `GitRepo.diff(file:in:)` already uses `--` before the path.
- `GitStatus` and the mounter use fixed argument lists.
